# Windows DLNA 接收端测试工具

本目录的 `go-dlna程序和源码.zip` 包含 `go-dlna.exe`、`main.go` 和原工具说明。这里的步骤针对该压缩包中的 **IPC 版**：它将 Windows 电脑作为 DLNA 接收端，通过本机 `mpv.exe` 播放媒体。`go-dlna不使用ipc.zip` 是另一种实现，配置和日志行为可能不同，不要混用两份可执行文件。

## 准备

1. 将 `go-dlna程序和源码.zip` 中的 `go-dlna.exe` 解压到单独的目录。
2. 解压本目录的 `mpv-x86_64-20261003-git-3186d369f9.7z`，找到其中实际的 `mpv.exe` 路径。也可以使用自己安装的 mpv；下载来源见 `其他.txt`。
3. 让电脑和运行 MBox 的手机连接同一个局域网，并允许 Windows 防火墙放行该工具的局域网通信。

## 配置与启动

在 `go-dlna.exe` 所在目录打开 PowerShell，运行：

```powershell
.\go-dlna.exe -v
```

首次运行会**询问** mpv 路径、设备名称和 HTTP 端口，然后在当前工作目录写入 `config.ini`。直接回车会采用源码中的默认值：mpv 路径 `C:\Program Files\mpv\mpv.exe`、设备名 `go投屏接收器`、端口 `9000`。如果 mpv 解压在其他位置，确认生成文件的 `mpv_path` 是实际路径；路径含空格时，建议生成配置后直接编辑 `config.ini`。配置示例：

```ini
[config]
mpv_path = C:\Tools\mpv\mpv.exe
friendly_name = MBox DLNA Test
http_port = 9000
```

`-v` 是详细日志模式；普通启动只打印配置和本机局域网 IP 等简要信息。IPC 版会在**启动时**打开并连接 mpv 窗口，投屏请求到来时在该窗口加载媒体，不需要等待第二个窗口弹出。窗口是否打开只能说明本机播放器已启动，不能代替投屏成功验证。

## 在 MBox 中测试

1. 打开 MBox 的投屏列表，等待搜索同一局域网的接收端。找到配置的设备名称后，选择它并尝试播放。
2. 如果列表没有找到设备，可使用投屏弹窗标题下方的“直连”，输入电脑的局域网 IPv4 和配置端口，例如 `192.168.1.10:9000`。MBox 会尝试读取接收端描述；不需要网页配对码。
3. 在 `-v` 窗口查看 `M-SEARCH`、设备描述和 `SetURI`/`Play` 相关记录，同时观察 mpv 是否实际播放。不要分享包含完整媒体地址或令牌的日志。

发现失败时先核对电脑和手机的网段、电脑 IP、`http_port`、Windows 防火墙，以及 `mpv_path`。若接收端已收到播放指令而 mpv 没有出画面，再检查媒体地址能否由电脑访问和 mpv 的输出。MBox 的设备发现与投屏行为仍需用户在真机上人工验证。
