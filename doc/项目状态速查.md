## 主要功能

- **背景图(用户自选)**:设置-主题颜色-设置背景图 → 二级页直接拿"正在调的背景"当预览:单指拖动位置、双指等比缩放(焦点锚定)。**改动只在点「确认背景」时写入配置**(不再边拖边生效),直接返回则整份草稿丢弃;草稿若没被改成用户自己的图,确认时会**清掉用户设置、让背景继续跟随主题默认**(浅/深主题即纯色),以后新增带默认背景图的内置主题/自定义主题时自动跟着走;「恢复默认」= 草稿回到"跟随主题默认" + 位置/透明度/遮罩回默认,同样要确认才生效。**没有背景图时预设/透明度/遮罩这排控件置灰**并提示去换图(纯色下这些设置没有意义)。「更换图片」放**标题栏右侧**(系统选图 SAF 免权限;导入时**必须是图片、拒绝 GIF、≤30MB**,然后纠 EXIF 方向、长边压到 2560、转成 WebP——照片 quality 90 有损/带透明通道无损——存进私有目录,旧副本换图后删除)。**底部控制面板是抽屉**(默认收起,只留"背景图设置"手柄,整屏看背景;手柄点击态是圆角 ripple)。**抽屉高度自适应**(代码里量,别写死):内容区高度 = min(内容自然高度, 可用高度上限),上限按"标题栏以下、屏幕以内"算(标题栏高 + 间隙 + 面板内外边距 + 手柄高);超上限时中间那块内容区(ScrollView)内部滚动,**底部"恢复默认/确认背景"两个按钮常显在面板最下面**(不参与滚动),所以内容再多也不会被顶出去裁掉。面板结构 = 手柄 + panel_content[ panel_scroll(可滚动设置项) + panel_actions(按钮行) ];代码按内容区高度反推滚动区高度,旋转/分屏后根布局高度变了会作废缓存、展开态就地重新封顶。展开后有:**预设**(全屏铺满=等比盖满屏幕超出裁掉 / 适应屏幕=按屏幕算,宽或高其中一边刚好铺满、另一边留边,整图可见 / 原图大小=原始像素 / 居中显示 / 四角=原图大小并把边贴到该角;尺寸与位置两项独立、当前项高亮,chip 走主题按钮色板大圆角)、**背景图透明度**(滑杆=背景图自身不透明度,100%=原图)、**背景遮罩开关**(遮罩不透明度固定 50%)。小图(如 100×100)按原始像素显示、可拖到任意角做点缀;大图默认铺满屏幕。**位置与屏幕尺寸解耦**:拖动/四角写的是锚点比例(贴左=0、居中=0.5、贴右=1),转横竖屏、换分辨率都还是同一观感(见上文"位置为什么是锚点比例");拖动的位移按该轴"可移动范围"(视图尺寸 − 图片尺寸,可能为负)换算,所以图既拖不出屏也拖不出缝,该轴刚好铺满时拖动无效

- **更新**:GitHub Releases 检查更新;APK 下载**代理优先,直连兜底**——先拼 `UpdaterConfig.getGithubDownloadProxy()`(默认 `https://gh-proxy.org/`)前缀,代理不可用自动回落 `https://github.com/CNShanJu/MBox/releases/download/<tag>/<apk>`,按 apkSize 校验避免代理返回错误页;说明弹窗按 releases 列表汇总"比当前新、不高于可下载最新版"的**最近 5 个版本**(新→旧),正文里 `<!-- dev -->…<!-- /dev -->` 开发者围栏(需独占一行)整段剔除,正文自带的版本标题与「相比 vX 的更新:」引言**单版本/跨版本都去重**
- **下载**:DownloadManager(并发1-5/断点续传/来源+剧名目录/m3u8→mp4/查重),入口=我的-下载;下载页两级(正在下载按剧名分组/下载完成按来源剧名文件夹),复用本地视频组件。**失败分级与换线路**(2026-09):分片 404/410 视为"源侧永久失效"——记入死片集合、后续补片不再请求(`补片跳过死片`)、不再重新解析地址;全部缺片都是死片时按放宽档判定(`MissingSegmentPolicy`:上限 max(8 片, 总片数 1%) 且 ≤10‰,940 片缺 8 片即放行,完成信息写"已完成(缺 N 片…少几秒画面)"),超出则立即失败并提示换源。**下载与播放用同一份净化清单**(2026-09):少数派(广告/占位)分片在下载时同样剔除 —— 净化逻辑已从 app 下沉到 `common/util/M3u8Purifier`(播放侧 `PlayFragment` 与下载侧共用)。这修掉了**"播放不缺、下载缺"**:那些少数派片在源站往往已被删(404),播放器不请求它们所以一路顺,下载器照单全下就报缺片(实测 940 片里 8 片 404 全是少数派前缀);净化后片序号变化由 `segments.sig` 指纹保护兜住(升级前正在下的任务会重下一次,不会拼错),完成信息写 `已完成(已过滤 N 片广告/占位分片)`。**缺的片先去别的线路取**(2026-09,最省流量的救济):同线路补片 3 轮仍缺(或剩余缺片全是源侧死片)时,先尝试**跨线路补片** —— 逐个探候选线路(重解析地址 + 只读拉它的播放列表),**必须切分一致**(片数相同 + 每片 `#EXTINF` 时长逐个在 ±0.5s 内)才允许取片,取回后还要过 **PTS 接缝校验**(标准 188 包 TS + 首/末 PTS 与本线路相邻已下分片接得上,容差 +2.0s/−0.5s),任一不过就删掉换下一条线路(切分一致才敢换);上限 30 片(再多接近整集重下,交给换线路)。补到的片正常参与合并,完成信息写 `已完成(补 N 片(来自其它线路),…合并为完整文件)`。**两条线路是不同转码/不同切分时,"第 i 片"不是同一段,所以宁可补不上也不拼错**;本线路整体不可用时才轮到"换线路重下"(整集重下),那才需要丢进度:候选在入队时按"同集"从详情页其它线路收集(`util/DownloadRoutePlan`,最多 3 条,集名优先、序号兜底),切线路后丢弃旧碎片整集重下(另一份播放列表的分片拼不进去),新线路解析失败会自动试下一条,全部试完才失败并提示 `(已换 N 条线路)`;**止损**:只有在"损失小"时才自动换(`util/RouteSwitchPolicy`:HLS 已完成 ≤200 片且 ≤25% 总片数;直链 ≤200MB 且 ≤25% 总大小),已下多了就不自动换、任务失败但**碎片保留**(同线路重试可续传),提示写 `(该线路分片不可用;已保留下载进度,重试可续传)` —— 换线路是整集重下,不能替用户悄悄扔掉几百 MB 进度;`episodeId` 不变(仍标识这一集)。保存根目录名为 `Download/MBox`(3.5.x 及以前是 `Download/TVBox`,**不做迁移**,旧目录需手动改名)。**m3u8 大小=抽样探测后推算**(2026-09):不再只按 `BANDWIDTH×时长`(声明值常写虚)或`片数×2MB`(拍脑袋),而是分层随机抽 12 片拿它们的真实字节数(HEAD 的 Content-Length,不认 HEAD 就退 `Range: bytes=0-0` 读 Content-Range 总长),截尾平均 × 片数(`common/util/HlsSizeEstimator`;字节范围清单直接读范围长度求和 = 精确值);单请求 8s 硬超时 + 整体 20s 预算,样本不够才退回码率口径,失败不阻塞下载 —— 这个数同时决定下载页"约大小"与启动前的磁盘空间预检。**存储看门狗(全下载链路唯一实现)**:下载过程中持续盯保存目录所在卷的可用空间(热路径 1s 缓存自检 + 有任务在跑时 2s 一轮后台巡检,任务全停线程自退),低于 1GB 就**暂停全部任务**并把原因写进任务信息(剩余空间 + 阈值,置 `STATE_PAUSED` 而非 源 90%、末尾样本读得出)再决定采用还是回退;真的回退时完成信息写明 `未封装为 MP4(保留 TS,原因见日志)`,不再让用户只看到一个莫名的 .ts
