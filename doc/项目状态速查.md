  - **气泡那层面的颜色必须在 `AttachPopupView#applyBg` 里接管,不能在 `onCreate` 补扫**(2026-09-27):XPopup 的 `AttachPopupView.applyBg()` 会把 impl 视图自己的 background **搬到外层 `attachPopupContainer`** 并把 impl 的底**置空**,搬过去那份是它从**自己的 Resources 重新解析**出来的(编译期/内置主题的 `@color/bg_float`),换肤注入(`ThemeContextWrapper`)与工厂注入都拦不到 —— 于是自定义主题下长按气泡/搜索页 ⋮「切换布局」气泡永远是内置白底。两种想当然的改法都不对:① 用 `ThemeDrawables.applyBackground` 装回一份重建的 `bg_bubble` 能上色,但**圆角/描边/尺寸会跟着换**(用户口径"tips 也是圆角不对了");② 只用 `ThemeSweep.apply(container)` 保住了几何,却因为它是**按值比对**(只换"还等于内置那份色"的视图)而**上不了色**(用户口径"圆角正确了,颜色又不走卡片的颜色了")。现解:几何交给 XPopup 自己,颜色由 `ThemeSweep.applyFloatFace(view)` **直接判定这块面就是 `bg_float`**(不猜原色),并且和 `apply()` 一样补两趟(当场 + `post`),`post` 在 `apply` 那一趟之后入队,避免"主题的 bg_float 恰好等于内置的 bg_surface/bg_card"时被后一趟改回页面档、丢掉浮层透明度。全仓只有 `AttachActionDialog` 是 `AttachPopupView` 子类(`SearchSuggestionsDialog`=PartShadow、`LastViewedDialog`=Position 都没有 `applyBg`,底留在 impl 上走正常注入),以后新增贴附型弹窗同理会踩这个坑。
  - **`ThemePillShapeContractTest` 不看 ripple 的 mask**(2026-09-27 补):`ripple_round_background` 只有一个 `@android:id/mask`(平时没有可见的底,只裁按下高亮),它的圆角挂在 `radius_background` 上,面板档调到 20dp 就让背景图设置页两条 44dp 的行报"药丸"。测试现在先把 mask 那段剥掉再找圆角(真正有可见底的 ripple 照旧会查),**不要靠往 `ALLOW` 里加控件来消红**。

  - **两种交互形态(逐页归属已定死)**:① **选择按钮** = 点击后 `setSelected(true/false)`,底色与文字色一起切成"纯色按钮"那一档(**代码只切 isSelected,不再手动换底换字色**)—— 运行日志页的分类/筛选键、设置背景页的「图片位置/大小」预设 8 键、播放器设置里的**倍速**键;② **点击按钮** = 点下去整键做一次**透明度 80% 的点击特效**再恢复(`ui/kit/WidgetPressEffect`,用 View alpha 才能连文字与图标一起淡)—— 搜索页的全部按钮(历史/热词 chip、搜索联想弹窗)、播放器设置里倍速**以外**的键(缩放/播放器/解码/横竖屏/字幕/音轨/重播/刷新/重置)、JSON 导入弹窗的「粘贴」键。

## 已知注意

- **⚠️ 打包最容易踩的坑:Android Studio 的"部署优化/Apply Changes"会让包丢资源**(2026-09-27 实测,用户连报四次"构建报 Missing AndroidManifest.xml entry")。机制与现场证据:
  - AS 的部署链路会把 **`app/build/intermediates/processed_res/<变体>/resources-<变体>.ap_` 删掉**(该变体的资源包),同时在 `app/build/outputs/apk/debug/` 留下一个 **149 条目的"部署载荷"**:只有 dex(33)+assets(24)+lib(12)+META-INF(69),**没有 `res/`、没有 `resources.arsc`、没有 `AndroidManifest.xml`、没有签名**(体积 42MB 看着很正常,极易被当成好包);
  - 后果一:AGP 增量打包把这个载荷当"上次打好的包"去补丁 → 抛 `java.io.IOException: Missing AndroidManifest.xml entry`;
  - 后果二(**更隐蔽**):`processed_res/<变体>/*.ap_` 没了而 Gradle 仍认为 `processDebugResources` 是最新的 → `packageDebug` 照样"成功",但打出来的是**无资源包**;这类包一旦上了机器,**资源层改动(圆角/颜色/布局/文案)全部不生效** —— 用户口径"圆角怎么改都不对/怎么设置都不生效"就有它一份;
  - 现在有两道机器兜底(都实测过):① `app/build.gradle` 里打包任务 doFirst 删掉"缺 AndroidManifest.xml 的旧 APK",`preBuild` doFirst 检查 `processed_res/<变体>` 里是否还有 `*.ap_`,没有就删掉该目录让资源自动重编(实测:WARN + `processDebugResources FROM-CACHE` 重建 + 打回 1369 条目的完整包);② `scripts/check-apk.mjs`(零依赖,校验 manifest/resources.arsc/classes*.dex/res 与条目数,坏包 exit 1)。
  - **手工验证 UI 改动的正确姿势**:装**完整包**(`app/build/outputs/apk/release/MBox_v<版本>_release_<日期>.apk`,1300+ 条目)或先在设备上卸载再 Run;不要拿 `outputs/apk/debug/` 那份 149 条目的包去装,也别指望"改完资源点一下 Run"就能看到 —— 换皮/圆角这类改动是**编译期资源**,必须完整安装。
