# 直播源说明(基于 vbskycn/iptv)

> 核心依据:[vbskycn/iptv](https://github.com/vbskycn/iptv) 的 README。
> 本项目默认直播源即来自该仓库,本文记录源地址、项目内实现与故障排查。

## 1. 直播源来源

[vbskycn/iptv](https://github.com/vbskycn/iptv) —— 国内可直连的 IPTV 直播源分享项目,免费、开源、无广告,支持 IPv4/IPv6 双栈访问。

- 直播源由仓库的 GitHub Actions 工作流**每 6 小时自动扫描验证更新**,保证时效与稳定
- 源全部自动收集自网络公开资源,项目本身不存储流媒体内容,**不保证源的可用性、稳定性与合法性**(官方免责声明,仅供学习交流)
- 配套站点:https://live.zbds.top/

## 3. 项目内实现

### 直播源优先级(重要)
**设置里配置的直播源优先**(设置 → 直播源;首次安装由 `App.putDefault(LIVE_URL)` 写入内置加速地址)。
订阅源里自带的直播只当**兜底**,顺序如下:

1. 源配置解析时(`ApiConfig.parseJson`)把两份直播分开存:
   - 主列表 `liveChannelGroupList` = 用户直播源(包成一个"待拉取"的代理分组);
   - 兜底列表 `getFallbackChannelGroupList()` = 订阅源自带的直播(内嵌频道分组,或订阅源里的直播地址包成的同类分组)。
   - 用户直播源为空(空串)时才把订阅源那份当主列表,并清掉兜底(免得失败后拿同一份重试)。
2. 进直播页(`LiveActivity.initLiveChannelList`):主列表是单个代理分组 → 拉取该地址并解析;
   主列表是内嵌分组(即没配直播源)→ 直接用。
3. 主直播源**没内容 / 拉取失败 / 解析失败** → 才退到兜底(订阅源的直播),同时 toast「直播源不可用,改用订阅源的直播」
   并写一条业务日志;兜底只走一层,不再递归。
4. 两者都没有 → 直播列表为空:主页不显示直播悬浮钮,直播页提示"频道列表为空"。

> 历史实现是"订阅源内嵌频道直接顶掉用户配的直播源"(列表里出现多分组时直播页只会用订阅源那份),
> 用户配的直播源形同虚设 —— 这就是上面这套优先级的由来,改这块代码前先读这段。

### 默认直播源
`app/src/main/java/com/github/tvbox/osc/base/App.java` 中 `putDefault(HawkConfig.LIVE_URL, ...)`:

```
https://gh-proxy.com/raw.githubusercontent.com/vbskycn/iptv/refs/heads/master/tv/iptv4.txt
```

(即上面的加速地址,首次安装自动生效;用户改过则以 Hawk 存储为准)

### 解析器 `util/live/TxtSubscribe.java`
- **txt 格式**:`频道名,url[#url2...]`(同频道多线路用 `#` 分隔),分组行 `分组名,#genre#`
- **M3U 格式**:`#EXTINF...,频道名` + 独立 URL 行;所有 `#` 指令行(`#EXTM3U`/`#EXTVLCOPT` 等)自动跳过,避免把头解析成频道
- 支持协议:`http / rtp / rtsp / rtmp / udp`
- 输出:`live2JsonArray` → 分组 → 频道 → 多线路 URL 列表

### 加载流程
```
LiveActivity.loadProxyLives(url)
  → HttpClient.get(url) 拉取文本
  → TxtSubscribe.parse → live2JsonArray
  → ApiConfig.loadLives → 频道分组列表 → UI 展示
```

### 频道列表显示约定
- 频道列表条目(`item_live_channel_new.xml` + `LiveChannelItemNewAdapter`)**只显示频道名**,占满整行宽度。
  解析阶段确实会给每个频道一个 `channelNum`(`ApiConfig.loadLives` 里跨分组累加的索引),
  但它**不是源里真实的频道号**,列表里显示它只会占宽、把长频道名(尤其电台)挤成省略号,故列表不显示;
  需要显示编号的地方是底部信息条 `tv_channel_bottom_number` 与换台大数字(`activity_live.showChannelInfo`)。
- 长频道名沿用全站惯例 `ellipsize="marquee"`(聚焦/遥控时滚动),不要改成别的省略方式。
  注意触摸设备上条目拿不到焦点,marquee **不会滚动**,宽度不够就只显示省略号 —— 所以频道列必须给足宽度。
- **左右两列宽度分工**(`activity_live.xml` 的 `ll_typeSelect`):分组列 `mGroupGridView` 固定
  `@dimen/dp_120`,频道列 `mChannelGridView` 用 `0dp + weight=1` 吃掉剩余全部宽度。
  **不要改回两列 `weight=1` 平分** —— 分组名多为 2~4 字,平分时它那一半基本是空白,
  而频道名(尤其"电台"分组的整句台名)只剩半列,再扣掉列表与条目的两层 10dp 内边距,
  360dp 宽的机器上文字区仅约 75dp(≈5 个字),正常台名一律变省略号。
  两列各自的 10dp 内边距已经构成视觉间距,外层不要再加 40/30/40dp 外边距(纯空白)。

### 线路抽屉 / 设置面板的文字样式(与选集 chip 同一套)
线路抽屉(`LiveLineSelectDialog` / `LiveLineSelectRightDialog`,两套壳共用 `dialog_live_line_select.xml`)
与直播设置面板的两个列表(`LiveSettingPanel`)用的是同一份条目布局与 adapter,文字口径**统一对齐
播放详情的选集 chip**(`RoundChip` + `item_series.xml`,见 `SeriesFlagAdapter` 的 detailStyle 注释):

| 状态 | 颜色 | 字重/字号 | 背景 |
|---|---|---|---|
| 未选中 | `text_sub_foreground`(次要灰) | 常规 16sp | 无 |
| 选中 | `colorPrimary`(主题高亮色) | **加粗 17sp**(基准 +1) | 无 |

- 基准 16sp 取自全屏选集抽屉(`AllVodSeriesRightDialog` 里 `setChipTextSize(16f)`),不是详情页的 12sp ——
  抽屉里两处字号一致,别把线路条目单独调小。
- **无边框无背景**:选中只靠文字色/字重/字号区分(`item_live_setting.xml`、`item_live_setting_group.xml`)。
  曾经条目挂 `shape_live_focus` 做聚焦底色(固定蓝 `accent_on_dark`),灰字压蓝底看不清、且与选集是两套观感,
  已去掉(该 drawable 随之删除);条目仍保留 `focusable`,遥控器照旧可导航,只是聚焦不再有底色。
  随之删掉的还有两个从无调用方的 `setFocusedItemIndex` / `setFocusedGroupIndex` ——
  它们只为绕开"蓝底压蓝字"而存在,底色没了就没有意义。
- 面板**左右两列必须同时改**:只改右列会变成"左列一块蓝底、右列没有",整个面板观感割裂。
- 条目行高固定 40dp,选中字号 +1 不会撑高整行,故这里不需要 RoundChip 那套 `TextLineHeight` 预留。

### 更换直播源
- 直播页设置 → **直播源弹窗**(`ui/dialog/LiveApiDialog.java`)输入新地址,保存并写入历史
- **历史直播源**(`ui/dialog/ApiHistoryDialog.java`):自动保存最近 20 条,按需切换

### 失败处理
- **源加载失败**:Toast 提示 + 空态(`LiveActivity.onLiveLoadFail`),不会卡在加载中
- **播放失败**:同频道多线路自动切换;所有线路都挂则停止并提示,**不自动切频道**
- 排查:`设置 → 运行日志` 会记录 `加载直播源/解析失败/加载失败` 日志

## 4. 故障排查速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 直播源打不开/加载失败 | 运营商污染 `live.zbds.top` 域名 | 换 gh-proxy 加速地址(项目默认即加速地址) |
| 频道大量失效 | 源本身更新周期或源失效 | 源每 6h 自动更新,等待或换源 |
| IPv6 频道全挂 | 上游提示大部分 IPv6 源已关停 | 换 IPv4 源 |
| 个别频道无法播放 | 单线路失效 | 同频道多线路自动切换,仍失败则提示 |
