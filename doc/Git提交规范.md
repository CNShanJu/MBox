# Git 提交规范（MBox 项目强制规则）

> 依据:https://blog.csdn.net/chenyajundd/article/details/139322838
> 适用:本仓库所有 commit,自 2026-08 起强制生效。

## 一、提交信息格式

```
<类型>[可选作用域]: <简短描述>

[可选详细描述]

[可选脚注]
```

### 组成部分说明

| 部分 | 必填 | 说明 |
|---|---|---|
| 类型 (type) | ✅ | 提交性质,见下表 |
| 作用域 (scope) | 可选 | 修改涉及的模块/组件(如 `下载`、`播放器`、`主题`、`doc`),增强定位精度 |
| 简短描述 (subject) | ✅ | **50 字以内**,简洁说明"做了什么";**不用句号结尾** |
| 详细描述 (body) | 可选 | 简短描述不够时补充具体修改点,空行后另起 |
| 脚注 (footer) | 可选 | 关联需求/BUG/Issue,如 `Fixes #123` |

## 二、类型 (type) 取值

| 类型 | 含义 | 影响 |
|---|---|---|
| `feat` | 新功能 | 次版本号 |
| `fix` | 修复 bug | 修订号 |
| `docs` | 仅文档修改(README、doc/ 下 md) | — |
| `style` | 代码格式调整(缩进、空格,不影响逻辑) | — |
| `refactor` | 代码重构(既非新功能也非修复) | — |
| `test` | 新增/修改测试代码 | — |
| `chore` | 构建流程、工具配置、资源清理等(不影响业务代码) | — |

> 本仓库常用补充:UI/交互类功能可加作用域,如 `feat(下载):`、`fix(播放器):`、`docs(目录):`、`chore(资源):`。

## 三、示例

```
feat(下载): 新增多选集下载弹窗与管理页

- 选集弹窗:圆角框/状态图标/固定3列/已下载去重/空选不关闭
- 管理页:全部暂停开始、设置入口、存储展示、状态徽标
- HLS 分段信息 TXT 记录 + 碎片校验 + 文件校验中/文件合并中阶段

Fixes #42
```

```
chore(资源): 清理未使用的图标与图片
```

```
fix(播放器): 全屏时视频未加载默认横屏,加载后按真实尺寸校正
```

## 四、强制要求

1. **每个 commit 必须带类型前缀**,禁止裸描述(如 `清理部分代码`、`补充上次提交`)。
2. 简短描述 ≤ 50 字、一句话、不加句号。
3. 一次提交只做一件事:功能 / 修复 / 文档 / 资源 分开提交,不混在一个 commit 里。
4. 提交前 `git status` 确认无多余文件混入。
5. 仓库根目录已提供 `.gitmessage` 提交模板,可用 `git config commit.template .gitmessage` 启用。

## 五、发版说明(Release/更新弹窗正文)另有规范

commit 信息是给开发者看的,可带 `type(scope)` 前缀与内部细节;**发版说明是给用户看的,禁止照搬 commit**——
只写用户关注的内容(新增功能 / 功能变更 / 移除停用 / 问题修复 / 体验与性能 / 兼容性注意),
内部事项(规则文档、依赖与构建、模块重构、单测门禁、版本号)包进 `<!-- dev --> … <!-- /dev -->` 围栏或直接不写。

完整要求见 `AGENTS.md` 第九章「发布与版本纪律」第 1~2 条;发布前用离线自检脚本过一遍:

```bash
node scripts/check-release-notes.js <正文文件.md>     # 或: node scripts/check-release-notes.js --stdin
```

命中开发者字样会非零退出并指出行号,提示挪进围栏或删除。
