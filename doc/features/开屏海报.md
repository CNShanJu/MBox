# 开屏海报（节气 / 节日）

开屏在当天命中二十四节气或节日时，用一张竖版水墨海报替代默认 Lottie 动画；海报**铺满整屏**，并按每张图自己的锚点裁切，保证图内标题不被切掉。同一天命中多个节日时，可从「我的」页进入海报大图页上下翻页查看并保存到相册。

规则红线见 `AGENTS.md` §七「节日图片开屏」，本文只讲机制与维护方法。

## 一、素材来自哪里

唯一素材表：`app/src/main/assets/splash/holiday_media.json`

```json
{
  "version": 1,
  "items": [
    {
      "id": "solar_term_xiaoxue",
      "name": "小雪",
      "url": "https://a1.boltp.com/2026/11/22/6b025c540788c.jpg",
      "anchorX": 1,
      "version": 1
    }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `id` | 必须与 `calendar/holidays.json` 的 `holiday.id` 完全一致（清明用 `qingming`，不是 `solar_term_qingming`） |
| `name` | 仅便于核对；**单测会校验它与节日目录同名 id 的 `name` 一致**，防止 id 挂错图 |
| `url` | 图片直链，必须 https |
| `anchorX` | 标题所在侧：`0` 保留左侧、`1` 保留右侧、`0.5` 居中 |
| `anchorY` | 可选，默认 `0`（贴顶）。横屏铺满只保留顶部一条，必须贴顶才看得见标题 |
| `version` | 可选，默认 `1`；参与缓存文件名，见「换图」一节 |

日期规则**不在这里**维护，仍只在 `calendar/holidays.json`。素材表只回答"这个节日的图是哪张、怎么裁"。

## 二、为什么要给每张图配锚点

海报是 9:16 竖构图，标题（"小雪""谷雨"这种大字）固定在顶部**某一侧**，且每张位置不同：

- **手机竖屏**（1080×2340 对 942×1672）：`cover` 只裁左右，各裁约 9%；
- **电视横屏**（1920×1080）：`cover` 只裁上下，只保留图片顶部约 32%。

所以两个方向各自只需要一个锚点：`anchorX` 决定竖屏保哪一侧的标题，`anchorY=0` 保证横屏保留顶部。**不要为了"完整显示"改回 `fitCenter`**——那样两侧会留一条生硬的边，而且用户明确否掉过。

### 怎么判断标题在哪一侧

自动统计"哪侧更暗"不可靠：谷雨、立夏的左侧有大片深色山体/竹枝，暗度会压过右侧的墨字，这两张都被判错过。

现在用**左右两侧放大裁切**核对：把每张图的左上角、右上角各放大 3 倍并排显示，一眼能看出大字在哪侧。核对脚本的做法是生成一个 HTML（每行 = 左裁 / 名称 / 右裁），浏览器截图后逐行看。

结论记录（2026-11-22 全量核对 41 张）：**20 张标题在左、21 张在右**，其中谷雨、立夏是唯一两处曾经判错的。

## 三、缓存

| 项 | 说明 |
| --- | --- |
| 位置 | `filesDir/splash_media/`（应用私有目录，卸载即清） |
| 命名 | `<id>-v<version>-<链接MD5前8位>.img` |
| 预取 | 每次冷启动在后台共享执行器里跑一次，窗口是**未来 30 天**内会命中的节日；当天的图优先下载 |
| 体积 | 41 张合计约 16MB，固定量级，不做时间淘汰 |
| 校验 | 落盘前按文件头确认是 jpg/png/webp，图床返回 HTML 错误页时不会把垃圾当海报缓存 |
| 清理 | ① 预取结束时删掉"不在当前素材表里"的旧文件；② 「设置 → 缓存管理 → 节日开屏海报」可手动清，清完下次启动自动补 |
| 升级兼容 | 旧命名（无版本号）在读取时改名复用，不会因为格式变更把已下载的图全部重下 |

### 换图

- **换成新链接**（重新上传必然得到新地址）：改 `url` 即可，链接哈希变化 → 新文件名 → 自动重下，旧文件随后被清。
- **同一链接覆盖内容**：`url` 不变则文件名不变，下载逻辑会判定"已存在"而跳过。此时把该条 `version` 加 1，强制刷新。
- **生效时机**：下次冷启动的预取，不是当场。
- **换了构图**：如果新图标题换到了另一侧，`anchorX` 必须一起改，否则仍按旧标题位置裁。

## 四、加载时序（为什么有"快速路径"）

首页从本地缓存秒开时，**开屏往往只存在 0.5~1 秒**，而节日目录（`holidays.json`）是首帧后才异步加载的，等它加载完再切换根本来不及。所以：

1. 冷启动第一帧：`SplashContentSelector` 先看 `HolidaySplashMediaStore.todayCachedPoster()` —— 这是上次预取结束时写进 `holiday_splash_media` 偏好的「今日海报路径 + 锚点」，只读一次 SharedPreferences + 一次文件存在性检查，不读 assets、不解析 JSON；
2. 命中就立刻以海报开场；没命中才播默认 Lottie，等目录就绪后再尝试切换（`maybeApplyHolidaySplashAfterCatalog`）；
3. 当天素材落盘后还有一次回调重试（`onTodayReady`），避免"刚下载完但已经错过开屏"。

**首次安装当天若正好是节气**：本地还没缓存 → 首启是默认动画，后台下载完成后**下次启动必然命中快速路径**。

## 五、兜底

任何一步失败都只退回默认 Lottie，不影响启动：

- 素材表损坏 → 整份作废（单条 URL 非法只跳过该条）；
- 缓存文件缺失/损坏/解码失败 → 回落；
- 加载超时（静态图 4 秒）→ 回落；
- 主题里设置了自定义开屏背景图且关闭了 Lottie 叠加时，以用户的主题设置为准，海报不覆盖。

## 六、查看与保存

- **「我的」页顶部节日名**（仅当天有节日时可点）→ 海报大图页：与开屏同一套铺满 + 锚点裁切，同日多节日上下翻页；「保存到相册」写 `Pictures/MBox`（Android 10+ 走 MediaStore 免权限，Android 9- 申请存储权限）。
- **设置 → 节日开屏预览**：**仅 debug 包**（按包名 `.debug` 后缀判断，正式包隐藏入口）。横向缩略图条 + 大图预览，默认选中今天命中的节日，缩略图标注"已缓存/未缓存（走网络）"。预览不写入正式缓存目录。

看图页与预览页**都用 ARGB_8888 解码**：Picasso 全局是 RGB_565（省内存），但水墨海报的米白到青灰是连续渐变，16 位色深会出色带并整体发灰。海报详情页不加任何遮罩；开屏在暗色主题下才压一层 `#1A000000`。

## 七、已知限制

- 视频素材未接入（`holidays.json` 的 `splash` 字段仍全为 false，网络海报只认素材表）；
- 电视上「我的」页节日名没有加 `focusable`（避免打乱遥控器焦点顺序），TV 查看海报目前只能走 debug 预览页；
- 海报是竖构图，横屏电视上只能看到顶部约三分之一，这是铺满的必然代价。
