空心组件边框线 = 它自己的文字颜色（2026-10-02，与 AGENTS.md §七 同步）：凡“无填充、只有描边”的组件（空心按钮 `BtnSecondary`、小组件键 `WidgetBtn`/`PageBgChip`、危险入口红字键 `BtnDangerGhost`、`bg_r_*_stroke_primary` 描边小件），描边色必须与该组件自己的文字色同源——普通键 = 文字主色（`btn_plain_text`/`text_foreground`）、危险入口 = 危险红 `#E5484D`、禁用态 = `text_disable`；**禁止**再挂“空心按钮边框线颜色”`btn_cancel_bg`（该键此后只服务没有自带文字的纯描边容器与输入框）。主按钮与实心选中态的填充、描边同取独立配置且不透明的 `btn_confirm_bg`（派生为 `btn_select_bg` / `btn_select_stroke`），底上的文字取 `btn_confirm_text`（派生为 `btn_select_text`）；文字主色 `brand` 仍控制正文与空心按钮的文字/描边。兼容迁移仅针对 schema ≤ 3 的旧主题：缺 `btn_confirm_bg` 或该值带透明度时静默沿用该主题的 `brand`，旧不透明值保留；用户保存时按 schema 4 落盘；当前读取只迁移内存，存量文件不会自动改写。后续移除旧格式分支前，必须先在后台原子升级尚未保存的旧主题文件并验证重读结果，迁移失败的文件继续兼容；分享/备份中的旧主题包也仍会经过导入解析，须继续迁移或明确提示该旧格式不再支持，不能只凭本机文件已升级就删分支。schema 4 缺键或显式透明值按同类型内置主题补齐；真正的空心操作统一用 `BtnSecondary`。日志筛选、背景预设与直播选中条共用实心选中规则。
空心按钮按下仍为空心（2026-10-01，与 AGENTS.md §七 同步）：`BtnSecondary`、`BtnDangerGhost` 与未选中的 `WidgetBtn` 在 `state_pressed` 下保持透明填充，描边与文字继续同色；点击反馈不能把空心键临时刷成实心。`BtnPrimary` 按下/短时禁用时保留原来的填充与文字对比，不得切到浅色半透明底导致白字难辨；只有真正的选中件才允许持续显示实心选中态。
点击型组件不得带“选中外观”（2026-10-01，与 AGENTS.md §七 同步）：`FlowTagLayout` 的 `app:max_select` 只给真·可选件；只做“点一下就触发动作”的 chip（搜索页历史/热词/相关搜索）一律不写 `max_select` —— 写了以后点击会 `setSelected(true)`，而 chip 的底 `selector_widget_btn` 带“选中 = 实心填充”状态，点过的词会变成一块选中色。新增点击型 chip 用无状态底（只有描边/无底），别挂带 `state_selected` 的选择器。
搜索页数据源：最近热搜 = `https://api.web.360kan.com/v1/rank?cat=3`（取 `data[].title` 前 10 条，两列带序号网格展示）；相关搜索 = `https://suggest.video.iqiyi.com/?if=mobile&key=<关键词>`（取 `data[].name`，内联 chip）。解析与 URL 编码收在 `util/SearchApiParsers`（纯逻辑带 JVM 单测）。

一、目标架构

依赖只允许自上而下：app/feature → 业务公开契约 → player/spider/download/share 等业务实现 → network/storage/state/log → 纯模型。业务实现放 internal 包，基础模块不得反向依赖业务或 UI；同一领域模型只定义一次，跨模块不共享可变对象。权威边界和源码门禁见 AGENTS.md 第一、二、六节。

二、已落地的模块边界与剩余工作

当前 10 个 Gradle 模块见第八节。原 core-model/core-utils/state 已合到 common（bean 纯模型、算法工具、系统状态）；spider-api/player-api 已回并 spider/player；原 crash/TabLayout/ViewPager1Delegate/quickjs 归入 thirdparty；ui-common 归入 app。契约与实现同模块后，通过 checkModuleDependencies 守源码边界。
core-network 收口网络客户端；core-storage 对外只暴露 Repository 和类型安全 Config，不暴露 DAO；download 只公开 DownloadFacade；share 以可插拔平台提供分享传输，局域网 HTTP 服务由 app 通过 LanShareHost 桥接。app/UI 访问爬虫必须走契约，不直连 ApiConfig、JsLoader 或 PlayUrlResolver。
播放器仍有 app 直用 MyVideoView、IJK、Media3 等残留，后续经 PlayerSession 和内核能力接口收口。旧 ExoPlayer 依赖已移除，Media3 版本统一为 1.4.1；真机播放行为由用户人工回归。

三、页面与业务逻辑拆分

PlayFragment 的目标是只负责 View 和生命周期；页面逻辑拆分为 PlayViewModel、PlayCoordinator、PlayerSession、SubtitleCoordinator 和 PlayHistoryRepository。PlayRequest、PlaySessionKeys、PlayedVodKey、SubtitleCoordinator、PlayHistoryRepository、PlayParseCoordinator 已抽出，剩余换源、解析与重试流程需结合真机回归逐步拆分。
DetailActivity 逐步拆为 DetailViewModel、DetailRepository、EpisodeSelectionState、DetailDownloadCoordinator 和 QuickSearchCoordinator；Activity 只处理导航、弹窗与视图事件。SourceViewModel 仅依赖 SpiderService 等契约，支持 FakeSpiderService 的 JVM 测试。

四、依赖注入

先由 app 的 AppCompositionRoot 统一装配 network、storage、spider、download、players。新代码通过构造函数注入接口，ViewModel 通过 Factory 获取依赖；静态 get() 暂作兼容入口，旧调用逐步迁移。是否引入 Hilt 取决于手动组合根的实际复杂度。

五、状态与事件

页面状态使用 ViewModel + LiveData，逐步 Kotlin 化后可采用 StateFlow；一次性页面事件使用明确的 Event 类型。下载与播放的跨页状态由 Facade 或 PlaybackSessions 订阅，系统网络与电量由 SystemStateMonitor 单点管理。EventBus 已全仓移除且依赖不在 classpath；禁止重新引入，跨页/模块事件用直调、Facade 订阅或明确监听器。

六、验收与安全红线

app/UI 不得新增 getCSP()、DownloadManager.get()、Hawk 裸读、具体爬虫实现直连、具体播放器内核 import 或自建线程池。业务后台任务由模块级共享执行器管理，并带取消或过期自检。Room 查询不得在主线程执行；网络客户端由 core-network 统一装配，不全局绕过 TLS 校验。
用户主动删除、清除、清空数据先弹确认框；取消后不得更改数据。可滚动组件保留内边距并设置 clipToPadding=false。图片加载统一使用 PicassoLoad 和 PosterPlaceholderDrawable，运行时占位置于 ImageView 背景层。
局域网服务按需启动；用户确认关闭后须立即停止对外监听、清除已配对设备并恢复仅本机回环。异常残留对外监听时须如实提示。路径拼接和解压均须防目录穿越，敏感网络操作须鉴权。其余主题、播放器样式、性能、构建与发布红线以 AGENTS.md 为准。
开屏只并行预取首页数据，用动画缓冲较长的数据加载；可见期间不装配或绘制首页 Fragment/组件，首页壳（ViewPager、底栏）也延迟 inflate，不能只设 GONE 掩盖已创建的组件。遮罩关闭后才创建首页 Fragment、装配子页面并绘制首帧，让用户看到组件出现。
数据先就绪可提前撤下动画；动画只播一次，先播完则停留最后帧 300ms 后直接进入首页，不继续等数据，也不设 20 秒内容兜底（素材解析或播放异常的兜底保留）。慢请求在入场后由首页接收同一轮结果，不得重复发起首屏请求。默认热播、订阅分类和关闭主页推荐时的首分类可在开屏预取，大块 XML/JSON 解析不能占用动画主线程；气泡、提示及自动检查等可见窗口须等首页首帧后再派发。节日素材选择集中在 SplashContentSelector，图片或视频类型按需扩展（与 AGENTS.md §七 同步）。
启动来源统一判定（2026-10-04 用户口径，与 AGENTS.md §七 同步）：只有用户主动从桌面/启动器重新打开 App 的真正启动，才触发开屏烟花、自动检查更新与首页“上次看到”；这些动作仍须遵守各自的首帧和展示时序。更换主题、订阅源、开启本地服务等配置生效流程发起的进程/任务重启属于内部重启：发起方须显式传递一次性启动来源标记，新主页创建时消费，不得仅以启动页进入 MainActivity、进程冷启动或 Activity 重建推断用户主动启动。后台返回、Activity 重建/系统恢复与内部重启均不触发上述用户启动动作，也不消耗烟花次数；内部重启仍正常完成开屏、配置装配与首页初始化。
“我的”页节日与启动烟花（2026-10-04 用户口径，与 AGENTS.md §七 同步）：“我的”页顶部左侧沿用当前应用名，大字单行显示（Debug 后缀也不得换行）；右侧仅在节日当天显示节日名（12sp），与应用名底部对齐，平日留空，不显示公历日期与农历日期；不要放到首页。节日烟花只在符合上述用户主动启动判定、开屏关闭且底栏完成首帧后播放；切后台再回来、应用内页面返回、Activity 重建/系统恢复及内部重启均不触发、不占次数。每组重复原有手指长按的 3 朵错峰动作，组与组也错开，不能同时齐射：普通宽度底栏在两个图标中心及中点各放一组，共 3 组 9 朵；底栏宽度达到 600dp 的大屏，再加入左边缘与左图标中心的中点、右图标中心与右边缘的中点，共 5 组 15 朵。元旦、除夕、农历正月初二至初十每个本地自然日最多 3 轮，第 2/3 轮分别距上一次实际发射至少 2 小时（满 2 小时可触发）；农历正月初一每次真正启动都发射，不限次数、无冷却。记录按本地日期持久化，次日启动时有旧记录才删除，没有记录就跳过；动画未启动不占次数。清理、准入或拒绝、发射、撤销都写 LogStore 业务日志。Debug 与 Release 均使用设备真实本地日期和时间；节日显示、烟花准入与跨日清理共用真实时钟，禁止固定节日预览日期。
节日规则以单独 JSON 为准（2026-10-04，与 AGENTS.md §七 同步）：现有节日和二十四节气的名称、简介、显示与否、是否播放启动烟花、每日轮数、下一轮冷却小时数统一在一份节日 JSON 中维护；二十四节气须能在“我的”页顶部节日位置显示，但节气不得触发烟花，即使 JSON 将其烟花开关设为 true 也忽略；公历 10 月 1 日国庆节应播放烟花。公历/农历条目使用相同日期字段与配置字段，只由 `type` 决定日期换算；农历闰月不得重复命中普通节日，同日节日撞日时显示与烟花分别匹配，不能因显示优先级漏播。受限节日沿用每天最多 3 轮、相邻实际发射至少 2 小时；春节初一用配置表达不限次数和冷却。冷却小时数只接受 1～23 的整数，缺失、非整数或越界均按 1 小时处理。JSON 同时预留按节日选择开屏素材的配置入口，未配置时保持现有开屏动画；禁止在代码里复制维护第二份节日规则。
节日文件固定在 `app/src/main/assets/calendar/holidays.json`：最上面的根级 `desc` 对象说明各字段意义，每条节日另保留字符串 `desc` 简介。每条都有 `id/name/desc/type/month/day/endDay/dateRule/term/includeLeapMonth/display/displayPriority/fireworks/splash`，公历/农历同构。`fixed` 按日期或日期段、`last_day` 按月末、`solar_term` 按节气计算（二十四节气均在 JSON 中显式列出）；农历正月初二至初十只参与烟花，不显示节日名。同一天跨历法的多个可显示名称须全部显示，用 `·` 分隔，按 `displayPriority` 从高到低排列；同一历法的可显示条目若重复配置同日/重叠固定区间、重复月末或同名节气，构建直接报错，跨历法真实撞日允许。烟花独立取 JSON 顺序第一条启用的非节气规则，每次启动仍只发一轮。`fireworks.maxLaunchesPerDay=0` 才表示不限次数，其余负数/非整数视为无效配置；`splash` 预留 `none/lottie/image/video` 类型的节日素材元数据，未配置的节日继续现有开屏效果。
后续真正启用节日专属开屏时，必须让冷启动的素材选择及时拿到节日目录，同时保持开屏动画立即启动、不等待目录 I/O；当前所有 `splash.enabled=false`，图片/视频渲染器尚未接入，不能仅改 JSON 开关就宣称图片/视频开屏可用。
组间时序补充：每次先随机打乱 3/5 个发射点的播放顺序，不能固定从左到右，每个点仍恰好放一组。第一组立即启动，后续每组相对前一组随机延后 100～500ms（逐组累加），不必等前组结束，允许交叠；每组内部仍按原长按动作错峰。“3/5 组”是单次启动中的动画组数，“每日最多 3 轮”是不同启动次数，不能混淆。
订阅启动的文本解码、Gson 建树、站点/解析/直播/解码配置装配、缓存与偏好落盘、Jar 校验/加载均交给 :spider 模块共享执行器；完整配置快照、嗅探规则与广告名单就绪后在主线程整体替换引用并派发回调，禁止后台原地修改已发布集合。配置与 Jar 请求须保留过期自检；Jar 下载按请求隔离，加载成功后才提交缓存和候选加载器，加载失败或请求过期须恢复旧缓存，进程中断后的备份也须在下次校验前恢复。首页分类与列表解析继续使用共享执行器（与 AGENTS.md §二 同步）。

   - 代码结构类：模块拆分与分层、接口抽取、命名与目录调整、死代码清理、内部机制替换
     （用户能感知则写“效果”，不写“机制”）；
   - 测试与门禁：单测、离线校验脚本、依赖门禁任务；
   - 纯内部实现细节（占位符实现方式、日志埋点、注释、性能埋点等）。
   判断标准：这条改动，普通用户看完能不能一句话说出“对我有什么用”；说不出就不写。
   哪怕一次发版里内部改动占绝大多数，也只写用户可感知的那几条，宁少而准。

3. 需要另存给开发者看的内部信息，包在 <!-- dev --> … <!-- /dev --> 围栏里（围栏须独占一行），
   App「检查更新」弹窗会自动剔除；GitHub 网页不渲染 HTML 注释，网页正文依旧完整。
   - 有用户可读内容的 doc/release-notes-<tag>.md 顶部至多写一个本版标题；CI 只原样贴手写正文，
     不得再自动补 ## <tag>。正文缺失或全在开发者围栏内时，不得留下用户可见的孤立版本标题。
   - App 汇总先清理连续重复标题及旧版对比引言，再判该版是否真有用户可读内容；纯标题/纯开发者
     版本不计入说明条目。只展示一个版本不得称“跨 2 个版本”；“从 vX 到 vY”必须以实际已安装版本为起点。
     发布前检查最终 Release 正文和 App 清洗结果；修已发布内容须编辑线上 Release，改文档或重跑旧 tag
     不会让旧工作流采用新逻辑。（2026-10-03，与 AGENTS.md §九 同步）

4. 发布前必须逐条自检：正文里不得出现 AGENTS、改进.txt、doc/、chore(、refactor(、docs(、ci(、test(、
   依赖、模块、重构、门禁、单测、Gradle、versionCode、commit 短号等字样；命中就挪进围栏或直接删掉。

5. 每次 push 若用户没有指定版本，先提升一次小版本号（versionName 末段 +1 并同步 versionCode）；
   同时把 debugVersionName 设为上一版实际发布的版本号，不能按新版末段减 1 推算（版本可能跳号）；
   打 tag 基于最新 versionName；出正式包基于最新 tag 对应版本；用户有明确说明时以用户说明为准。

6. debug 构建产物严禁提交（除非用户明确要求并二次确认）。
   发布含中文内容必须显式 UTF-8 写入并以字节发送，发布后抽查是否出现连续 “?” 乱码。

## 下载鉴权与存储的持续约束（2026-10-01）

- 下载权限必须按实际保存路径判断；Android 11+ 的应用私有目录不得要求“所有文件访问”权限。仅 Wi-Fi 等待属于排队状态。
- URL、Cookie、Referer、UA 与自定义请求头通过公开契约刷新并原子替换；下载模块不得直接访问 WebView、ApiConfig 或具体登录实现，暂停/过期任务不得回写结果。
- HLS 续传必须核对媒体序列、分片路径与顺序、字节范围、密钥/IV、init 布局；不能仅凭数组下标复用，也不能仅因短时鉴权参数变化清空进度。无法安全确认时暂停或清理后重下。
- 401/403 先有限续期，404/410 先有限短重试并刷新清单，再确认永久缺片；登录失效必须可恢复暂停，不得高频循环请求旧地址。分片 URL 不整表持久化。
